## IPC 是什么

IPC 是 Inter-Process Communication，进程间通信。

在 Electron 中：

- Renderer Process 运行 React 界面。
- Main Process 管理窗口、文件、Session 和系统能力。
- 招聘网站运行在独立的 WebContents。

这些进程不能直接调用对方的 JavaScript 函数，因此通过 IPC 传递消息。

JobLoop 的调用链：

```text
React
  → preload 暴露的 window.jobloop
  → ipcRenderer.invoke(channel, payload)
  → Main Process ipcMain.handle()
  → BrowserController
  → 返回 IpcResult<T>
```

preload 是安全代理，不把 Node.js、fs、child_process 或 ipcRenderer 整体暴露给页面。

## IPC 返回协议

成功：

```ts
{
  ok: true,
  data: T
}
```

失败：

```ts
{
  ok: false,
  error: {
    code: string;
    message: string;
  }
}
```

所有 Renderer 调用必须处理失败分支，不能假设主进程操作一定成功。

## Channel

Channel 统一定义在：

```text
shared/ipc-channels.json
```

主进程和 preload 使用同一份定义，避免字符串不一致。

## 错误码

```text
INVALID_URL
INVALID_BOUNDS
BROWSER_UNAVAILABLE
PAGE_BUSY
NAVIGATION_FAILED
CAPTURE_FAILED
UNTRUSTED_SENDER
INTERNAL_ERROR
```

未预期异常不会把文件路径、堆栈或内部实现细节返回给 Renderer。

## BOSS 直聘兼容修正

- 所有 HTTP/HTTPS 新窗口链接都留在内嵌浏览器中，符合浏览器使用预期。
- `mailto:` 等非网页协议交给系统处理。
- Unicode 私有区字符不再显示为 `�`；疑似薪资行会整行替换为中文提示。
- 检测到 BOSS 的 SVG 薪资或私有字体时，界面提示薪资需要人工确认。
- 不尝试破解站点防抓取字体；后续由正式站点 Adapter 或人工校对处理薪资。

# 技术架构

## 目标架构

```text
Electron 桌面应用
├── React Agent 工作台
│   ├── 简历画像
│   ├── 岗位分析
│   ├── 打招呼
│   ├── 投递看板
│   └── 模拟面试
│
├── WebContentsView
│   └── 内嵌招聘网站
│       ├── 用户手动登录
│       ├── 持久化 Session
│       └── 当前岗位页面
│
├── Browser Bridge
│   ├── 页面元信息
│   ├── 岗位提取
│   ├── 页面截取
│   └── 经审批的页面动作
│
└── Agent Service
    ├── 模型 Provider
    ├── Agent Loop
    ├── 工具注册
    ├── 会话与任务状态
    ├── MCP Client
    └── 运行事件流
         │
         └── MCP Server
             ├── 候选人画像
             ├── 岗位
             └── 投递记录
```

## 技术选型

| 领域 | 方案 | 原因 |
|---|---|---|
| 桌面外壳 | Electron | WebContentsView 支持嵌入第三方站点，TypeScript/React 迁移成本低 |
| 前端 | React + TypeScript + Vite | 与现有经验一致 |
| 样式 | 待定，优先轻量方案 | 不为 UI 组件库增加架构复杂度 |
| 后端 | 本地 Node.js/TypeScript | 与前端共享类型，适合 MCP |
| 数据库 | SQLite | 本地优先、易演示、零外部依赖 |
| Agent 运行时 | Provider Adapter + 轻量 Agent Loop | 避免与单一模型或框架强绑定 |
| 工具协议 | 本地领域工具 + MCP Server | 在需要跨进程/可复用时使用 MCP |
| 事件流 | SSE 或 Electron IPC 事件 | 流式展示 Agent 和工具运行状态 |
| 文件解析 | PDF/DOCX 解析库 | 第一版只处理实际简历格式 |

## 进程边界

### 主进程

- 窗口和 WebContentsView 生命周期。
- Session 与权限管理。
- 招聘网站导航策略。
- 受控页面读取。
- 本地文件访问。

### 渲染进程

- Agent 工作台 UI。
- 表单、看板、图表和面试界面。
- 通过受控 preload bridge 发出请求。

### Agent 服务

- 模型调用。
- Agent Loop。
- 工具注册和调度。
- 上下文压缩。
- 任务事件和持久化。

### 招聘网站页面

- 只处理招聘业务本身。
- 不接触本地数据库、文件系统或模型密钥。
- 不直接访问 Node.js API。

## 浏览器读取策略

按可靠性依次使用：

1. 目标站点信任 Adapter。
2. 通用正文、JSON-LD 和可见文本提取。
3. 当前岗位区域截图或可访问性树。
4. 用户手动粘贴和修改。

Agent 默认获得结构化 `JobPosting` 和必要的页面摘录，不默认获得 Cookie、登录凭据或完整页面历史。

## 工具设计原则

- 工具参数使用严格 Schema。
- 读取工具与写操作工具分离。
- 写操作必须有明确目标和人工审批。
- 工具错误作为结构化结果返回模型。
- 页面 DOM 变化不能直接导致误操作。
- 所有业务写入支持幂等标识。
- 不向模型暴露任意 JavaScript 执行能力。

## 可观测性

每次 Agent 运行至少记录：

- 运行 ID 和会话 ID
- 当前模型
- 用户输入摘要
- 工具名称、参数摘要和结果状态
- 开始、结束和耗时
- 错误类型
- 人工审批结果
- 关联岗位和投递记录

不得记录密码、Cookie、完整认证头和不必要的简历原文副本。

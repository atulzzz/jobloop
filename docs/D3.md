## 目标

把当前页面阅读能力推进到领域数据层：

```text
BOSS 岗位页 HTML
  → BOSS Adapter
  → JobPosting
  → 表单确认
  → 后续匹配与投递
```

## 支持的页面类型

BOSS Adapter 需要支持两种页面，而不是只支持岗位详情页：

### `detail`

地址形如：

```text
https://www.zhipin.com/job_detail/{jobId}.html
```

主岗位信息位于 `.job-banner`。

### `search-result`

地址形如：

```text
https://www.zhipin.com/web/geek/job?query=...
```

页面左侧是岗位列表，右侧是当前选中岗位详情。Adapter 必须：

- 只读取右侧当前详情，不读取列表中的其他岗位。
- 从选中卡片或右侧详情链接中提取稳定岗位 ID。
- 保存 `pageUrl` 为搜索页地址。
- 保存 `sourceUrl` 为该岗位规范详情地址。

## 需要创建的文件

### `electron/job-model.mjs`

至少导出：

```js
export function createJobPosting(input) {}
```

`JobPosting` 应包含：

```text
schemaVersion
source
sourceJobId
sourceUrl
pageUrl
pageKind: detail | search-result | unknown
title
company
city
salaryText
salaryStatus: readable | unreadable | missing
experience
education
description
skills
missingFields
capturedAt
```

### `electron/adapters/boss-adapter.mjs`

至少导出：

```js
export function isBossJobUrl(url) {}
export function extractBossJob({ html, url, capturedAt }) {}
```

实现要求：

- 只接受 BOSS 的 `/job_detail/...html` 页面。
- 同时接受 BOSS 的 `/web/geek/job` 搜索页。
- 从 URL 中提取稳定岗位 ID，忽略 `securityId` 等会话参数。
- 搜索页必须从右侧详情或选中岗位卡片确定岗位 ID，不能取列表第一项冒充当前岗位。
- 优先读取岗位主区域，避免误取相似职位和推荐职位。
- SVG 或私有字体加密薪资标记为 `unreadable`，不猜测金额。
- 薪资不可读且确实不存在时标记为 `missing`。
- 普通字段缺失写入 `missingFields`。
- 不把 `客户公司：` 前缀保存在公司名称中。
- 清理重复空白。

1. 使用 `npm run dev` 启动。

快照会移除脚本、表单输入值，并清理 URL 查询参数。仍应在公开任何内容前人工检查，避免泄露个人信息。

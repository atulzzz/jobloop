# MVP 验收标准

## 浏览器

- [ ] Electron 能够打开目标招聘网站。
- [ ] 用户可以自行完成登录。
- [ ] 应用重启后保持登录。
- [ ] 招聘网站页面不能访问 Node.js 或本地数据库。
- [ ] 未授权域名不会复用招聘网站 Session。

## 岗位采集

- [ ] 当前岗位能够一键提取。
- [ ] 提取结果包含标题、公司、JD 和来源 URL。
- [ ] 缺失字段有明确提示。
- [ ] 用户能够修改提取结果。
- [ ] 页面结构变化时能够回退到通用提取或人工粘贴。

## 简历画像

- [ ] 支持实际使用的 PDF/DOCX 简历。
- [ ] 画像中的事实可以追溯到简历证据。
- [ ] 不存在的经历、技能或指标不会被生成。
- [ ] 用户可以确认、编辑并保存画像版本。

## Agent

- [ ] 至少完成一次模型 → 工具 → 结果 → 继续推理的闭环。
- [ ] 界面可看到工具名称、状态和结果摘要。
- [ ] 工具失败时模型收到结构化错误。
- [ ] 支持取消或超时。
- [ ] 至少三个业务工具通过 MCP Client 调用了 MCP Server。

## 岗位评估

- [ ] 硬性条件与加权评分分开。
- [ ] 每项评分包含证据和置信度。
- [ ] 修改用户权重后分数按预期变化。
- [ ] 风评信息不足时显示“信息不足”，不编造结论。

## 打招呼

- [ ] 引用真实简历和岗位信息。
- [ ] 不声称简历中不存在的技能或成果。
- [ ] 用户可以编辑和复制。
- [ ] 第一版不自动发送。

## 投递管理

- [ ] 可以从岗位创建投递记录。
- [ ] 状态变化生成历史事件。
- [ ] 支持下一步行动和日期。
- [ ] 重复提交不会创建重复投递。
- [ ] Excel 导入可预览、校验和生成报告。

## 看板

- [ ] 投递数、回复率和面试数来自同一数据源。
- [ ] 支持查看停滞岗位。
- [ ] 可生成基于状态的下一步建议。

## 模拟面试

- [ ] 支持技术面试和行为面试。
- [ ] 至少完成 5 轮对话并支持追问。
- [ ] 按住说话录音后可以转成文字。
- [ ] 结束反馈引用真实回答内容。
- [ ] 语音接口失败时可以继续使用文字模式。

## 工程与演示

- [ ] 全新环境可按照 README 启动。
- [ ] 有架构图、数据流和关键决策文档。
- [ ] 有 3～5 分钟演示。
- [ ] 简历描述与项目实际能力一致。
- [ ] 项目负责人能够解释核心链路和至少三个失败场景。

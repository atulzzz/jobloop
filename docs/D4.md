# D4 岗位确认与校对

## 目标

将 D3 的只读结构化岗位升级为用户可编辑、可确认的岗位记录。

```text
BOSS 页面
  → JobPosting
  → 可编辑确认表单
  → validateJobConfirmation
  → 用户确认的 JobPosting
```

## 项目负责人手写部分

实现：

```text
shared/job-confirmation.mjs
```

导出：

```js
export function validateJobConfirmation(draft, options = {}) {}
```

返回值：

```js
{
  valid: boolean,
  job: JobPosting,
  errors: Record<string, string>
}
```

## 校验规则

- 不修改传入的 `draft`。
- 清理字符串首尾空格。
- 标题、公司、来源 URL 必填。
- `sourceUrl` 只接受 HTTP/HTTPS。
- 用户填写有效薪资后，状态改为 `readable`。
- 空薪资本身不阻止确认：
  - 原状态 `unreadable` 保持 `unreadable`。
  - 原状态 `missing` 保持 `missing`。
- 技能标签去空格、去重并移除空值。
- 城市、经验、学历、描述、技能缺失不阻止确认，但进入 `missingFields`。
- 设置 `confirmedAt`，测试可注入固定时间。

## 技能标签修正

搜索页技能不再使用“跳过头两个标签”的位置假设。

当前规则：

- 使用显式正则识别经验标签。
- 使用显式正则识别学历标签。
- 排除互联网、办公条件、福利等已知非技能标签。
- 剩余标签作为候选技能。
- 用户可在确认表单中最终修改技能。

这仍然属于页面标签启发式，而不是 JD 语义理解。后续 Agent 阶段可以结合 JD
证据补充技能，但结果仍需用户确认。

回归测试覆盖标签乱序、行业标签和办公条件混入的情况。
